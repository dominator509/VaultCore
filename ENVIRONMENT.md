# ENVIRONMENT.md

## Required Tools
- `git`
- `sh` POSIX shell (macOS, Linux); PowerShell shims on Windows added in EP-009 if needed
- `rustup` with toolchain pinned by `rust-toolchain.toml` (Rust 2021 edition, MSRV pinned in EP-001)
- `cargo-nextest` (test runner) and `cargo-deny` and `cargo-audit`
- `pnpm` (TS workspace, version pinned in `package.json` `packageManager` field)
- `node` matching the version range in `app/package.json`
- Platform Tauri prerequisites (system webview, code-signing toolchain per target)

## Versions
- Pinned via `rust-toolchain.toml`, `Cargo.lock`, `pnpm-lock.yaml`, and `app/package.json`.
- Do not bump versions without an ExecPlan covering re-verification of invariant enforcement tests.

## Package Manager
- Rust: `cargo`
- TypeScript: `pnpm`
- Tauri shell: `pnpm tauri ...`

## Environment Variables
> All variables apply at build/dev time. Runtime configuration is carried by the signed SpecAnchor, not environment variables. Never put secrets in env vars.

| Name | Required? | Environment(s) | Example Value | Secret? | Description | Validation Rule |
|---|---|---|---|---|---|---|
| VAULTCORE_DEV_DIR | Optional | local | `./.vaultcore-dev` | No | Directory for dev vault, dev SpecAnchor, dev logs. Created on first dev run. | Must be writable; must not point at a real user vault. |
| VAULTCORE_LOG_LEVEL | Optional | local/test | `info` | No | Builder/Verifier log level. | One of `trace`, `debug`, `info`, `warn`, `error`. |
| VAULTCORE_TEST_VAULT | Optional | test | `./tests/fixtures/vault_small.db` | No | Path to a fixture vault for integration/E2E tests. | Must point at a fixture under `tests/fixtures/`. |
| VAULTCORE_SPECANCHOR | Optional | dev | `./.vaultcore-dev/specanchor.signed` | No | Path to a dev SpecAnchor. Generated by `cargo run -p vaultcore-cli -- specanchor generate`. | Must verify against the dev signing key. |
| VAULTCORE_DISABLE_TELEMETRY | N/A | all | `1` | No | Telemetry is off by default; this is a no-op asserted by a test. | Must always read as off. |
| CI | Optional | CI | `true` | No | Enables CI-specific paths (no interactive prompts). | Set by GitHub Actions. |
| TAURI_SIGNING_PRIVATE_KEY | Required for release builds | release CI | (signed-out) | Yes | Tauri updater signing key. Loaded from CI secret store. | Must be present only on release jobs. |
| MACOS_CODESIGN_IDENTITY | Required for macOS release | release CI | (signed-out) | Yes | macOS Developer ID Application identity. | Must be present only on macOS release jobs. |
| WINDOWS_CODESIGN_PFX | Required for Windows release | release CI | (signed-out) | Yes | Code signing certificate. | Must be present only on Windows release jobs. |

If a variable is added, append a row and update `EP-009` and `RELEASE.md`.

## Secrets
- Long-term signing keys (project signing key, SpecAnchor signing key, platform code-signing keys) live in the project's secret manager and are injected into CI only for release jobs.
- Never commit real secrets to the repo.
- Never write secrets to local files outside the OS keychain on dev machines.

## Local Development Setup
1. Clone the repository.
2. Read `AGENTS.md`, `COMMANDS.md`, and the active ExecPlan.
3. Run `./scripts/preflight.sh`.
4. Run `./scripts/install.sh`.
5. Generate a dev SpecAnchor: `cargo run -p vaultcore-cli -- specanchor generate --out ./.vaultcore-dev/specanchor.signed --dev`.
6. Start the app in dev mode: `pnpm --dir app tauri dev`.
7. The dev app uses a sandboxed vault under `./.vaultcore-dev/`.

## Local Database Setup
- SQLite vault files are created automatically by the Builder under `VAULTCORE_DEV_DIR`.
- Schema migrations are embedded; run `cargo run -p vaultcore-cli -- migrate --dry-run` before applying.

## Test Environment Setup
- Tests use fixtures under `tests/fixtures/` and `app/tests/fixtures/`.
- Test SpecAnchor is generated with the dev signing key and never used outside tests.
- Each test creates a fresh temporary vault under `target/test-vaults/<test-name>/`.

## Staging Environment Setup
- Not applicable in the traditional sense. "Staging" for VaultCore is a release-candidate Tauri bundle built from the `release-candidate` branch, run by the release manager on supported platforms, and validated against the smoke test.

## Production Environment Setup
- "Production" for VaultCore is the user's installed application.
- Production builds are signed with platform code-signing identities and the Tauri updater key.
- No production server.

## Configuration Validation
- The SpecAnchor is the only runtime configuration; it is signed and validated at startup. A tampered SpecAnchor causes startup failure.
- Builder and Verifier emit `config: ok` log lines after successful validation; smoke test asserts on these.

## Environment Parity Rules
- Dev and release builds share the same source tree; differences are limited to signing, build profile, and the SpecAnchor used.
- CI runs the same scripts as local (`./scripts/verify.sh`).
- Differences across platforms are limited to OS-specific adapters under documented module paths.

## Troubleshooting
- `preflight: fail required script missing` → restore `scripts/` from git.
- `SpecAnchor verification failed` → regenerate the dev SpecAnchor; do not bypass verification.
- `Verifier countersignature rejected` → confirm session is unlocked; check role; do not relax policy to make it pass.
- Tauri dev fails to spawn Verifier → check OS permissions for spawning child processes; check logs at `VAULTCORE_DEV_DIR/logs/`.
